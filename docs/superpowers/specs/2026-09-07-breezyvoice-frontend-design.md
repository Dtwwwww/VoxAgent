# BreezyVoice 台湾腔女声前端接入设计

## 目标

将已在本机验证可运行的 BreezyVoice 台湾普通话女声加入 Web 前端音色选择器，支持用户选择和试听，同时不破坏当前实时语音通话的稳定性。

## 约束与事实

- BreezyVoice 模型约 2.6GB，模型文件位于本机数据目录，不提交到 GitHub。
- 当前 CPU 实测生成约 10 秒音频需要数分钟，因此不适合实时通话链路。
- 现有 WebSocket 音色协议已经支持服务端音色目录、音色选择和试听，公开协议不暴露引擎及本机路径。
- 当前 Kokoro 是实时/常规离线音色，必须继续作为默认可用回退。

## 用户体验

音色选择器新增一张本地卡片：

- 名称：台湾腔女声
- 标识：BreezyVoice
- 描述：台湾普通话女声；高质量朗读，生成较慢
- 性别：女声
- 状态：可选择、可试听

选择 BreezyVoice 后，前端保存 `voice_key`，在卡片上显示“已选择”。试听按钮显示现有的试听/停止试听状态。实时通话开始时不切换到 BreezyVoice 实时合成；实时链路继续使用 Kokoro，避免长时间阻塞。界面描述明确提示该音色适合手动朗读，不适合实时通话。

## 后端设计

1. 扩展服务端音色目录，新增 `breezy_tw_female`，引擎标记为 `breezyvoice`，但保持引擎字段仅服务端可见。
2. 扩展 TTS 引擎协议和生产工厂，增加 BreezyVoice 适配器。适配器懒加载模型，首次调用前校验模型目录、官方女声参考音频和 G2PW 目录；缺失时返回可读的可恢复错误。
3. BreezyVoice 合成放入线程池/后台任务，不阻塞 asyncio 事件循环；实时对话合成不调用该引擎，仅手动朗读和试听允许调用。
4. 保留现有错误事件格式，失败时返回 `tts.error` 或 `error`，并且不影响 Kokoro 音色。
5. 增加配置项：模型目录、参考音频路径、G2PW 目录均支持环境变量/数据目录默认值。

## 前端设计

1. 使用服务端 `voices.available` 动态展示 BreezyVoice，不硬编码模型路径。
2. 音色卡片增加“高质量朗读 / 非实时”提示样式；选择与试听沿用现有状态管理、取消和错误处理。
3. 选择保存到现有本地设置；服务端未提供该音色时自动回退默认音色。
4. 试听中禁用冲突操作，保留现有停止试听行为。

## 测试与验收

- 后端：目录 schema、引擎分派、缺失模型错误、BreezyVoice 懒加载均有单元测试。
- 前端：音色卡片展示、选择/持久化、试听按钮和非实时提示有组件测试。
- 集成：启动服务后 `voices.available` 包含 `breezy_tw_female`；选择后收到 `voice.selected`；缺失模型时其他音色仍可试听。
- 不提交模型二进制及本机临时文件。
