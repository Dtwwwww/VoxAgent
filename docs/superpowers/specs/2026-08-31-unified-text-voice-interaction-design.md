# VoxAgent 统一文字与语音交互设计

**日期：** 2026-08-31  
**状态：** 已获用户确认
**适用阶段：** Plan 02 Streaming Voice Loop

## 目标

VoxAgent 在同一个 Web 会话中同时支持文字输入和连续语音输入。两种输入共享消息列表、
会话上下文、模型回复与打断规则，用户无需切换到另一张页面，也不会因为改变输入方式而
丢失上下文。

首版只运行在 `localhost`，使用 Plan 1 已验证的 Ollama、Qwen、SenseVoice 与本地 TTS。
本设计不加入云端 API、唤醒词、持久记忆、文件工具或系统控制。

## 参考交互

本设计采用主流产品共有的“同一聊天中混合文字和语音”结构，而不复制其视觉样式：

- [ChatGPT Voice](https://help.openai.com/en/articles/20001274-chatgpt-voice)：语音位于同一聊天，
  回答同步显示文字，可在语音中打断，也可继续使用文字。
- [Microsoft Copilot Voice](https://support.microsoft.com/en-us/microsoft-365-copilot/frequently-asked-questions-about-voice-features-in-microsoft-365-copilot)：
  从消息输入框进入语音，支持实时字幕、说话打断，并可回到文字继续同一会话。
- [Gemini Live](https://support.google.com/gemini/answer/15274899)：支持说话或点击打断，
  字幕可独立开启。
- [豆包](https://www.doubao.com/legal/feature_intro)：同时提供语音转文字、语音回答和随时打断。

## 页面结构

页面保持一个聊天布局：

1. 顶栏显示“VoxAgent 声灵”、本地模型名称、连接状态和当前音色入口，不展示数据目录、
   会话令牌或其他本机敏感信息。
2. 中部消息列表使用最大宽度约 960 px 的单列对话流。页面背景为中性浅灰，消息卡片
   保持高对比度；不复制任何参考产品的商标、配色或插画。
3. Agent 消息固定在左侧，名称显示为“Agent（声灵）”，使用浅色卡片、Agent 头像和
   最大约 72% 的内容宽度。流式生成时在同一张卡片内追加文字。
4. 用户消息固定在右侧，名称显示为“用户”，使用主题色气泡和最大约 68% 的内容宽度。
   语音识别结果仍显示为普通文字，但增加麦克风图标与“语音”来源标记。
5. 双方不仅靠颜色区分，还使用方向、名称、头像和来源图标；布局在 1280×720 和浏览器
   200% 缩放下仍保持可操作。
6. 底部组合输入区固定显示自动增高的文字输入框、发送按钮、麦克风按钮、当前音色快捷
   入口和“朗读文字提问的回复”开关。输入框最多显示五行，`Enter` 发送、
   `Shift+Enter` 换行、`Esc` 停止当前生成或朗读。
7. 麦克风启用时，输入区显示实时识别文字、红色录音指示和明确的“正在聆听”文字；
   不以动画替代状态说明，也不禁用文字输入。
8. 状态区域使用 `aria-live="polite"` 显示连接中、正在聆听、识别中、思考中、正在说话、
   已被用户打断和错误。
9. 每条已完成的 Agent 消息提供“复制、朗读/停止朗读”按钮。被取消的回复保留已经展示
   的文字并标记“已停止”，但不写入后续模型上下文。

语音提问默认生成并播放语音；文字提问默认只显示文字。用户打开全局开关后，后续文字
提问也自动生成语音。单条消息的“朗读”按钮按需重新合成该消息，不长期保存音频。

## 音色选择

音色设置参考豆包“多种自然音色可选择”的产品逻辑，但使用 VoxAgent 自己的名称、布局和
本地模型。首版不直接展示 Kokoro 的技术说话人编号，而是从本机可用声线中精选 4–6 个
普通话表现稳定的选项：

- 每张音色卡片显示易懂名称、简短风格描述、试听按钮和选中标记。
- 首版目标分类为“清澈女声”“温柔女声”“沉稳男声”“阳光男声”；只有试听确认符合
  描述的声线才能使用该名称。
- 试听使用同一句固定、无敏感信息的普通话，时长约 3–5 秒；切换试听会立即停止上一段。
- 语速只提供 `0.8`、`1.0`、`1.2` 三档，默认 `1.0`，与后端允许范围一致。
- 选择立即作用于后续自动朗读和单条朗读，并只保存在当前浏览器的 `localStorage`；
  不写入聊天上下文，不传给 LLM。
- 后端只接受公开目录中的稳定 `voice_key`，由服务端映射到引擎和原生 `voice_id`，客户端
  不能任意提交原生编号。
- Kokoro 提供多说话人候选；Melo 当前只有一个说话人，只作为基准测试或兼容性回退，
  不伪装成多个音色。
- 如果音色加载或合成失败，保留完整文字回答，并允许切回默认声线。

Plan 2 使用固定候选集生成盲听样本：Kokoro 女声原生 ID `3`、`13`、`27`、`43`，男声
原生 ID `58`、`69`、`85`、`98`。用户在不知道编号的情况下完成风格匹配与自然度评分，
最终映射写入 `backend/src/voxagent/speech/voice_catalog.json`。目录至少包含一个默认音色；
未经试听确认的候选使用“女声候选 N”或“男声候选 N”，不得提前标注主观风格。

## 统一会话与上下文

文字输入和最终 ASR 文本进入同一个内存会话历史。每条用户消息记录输入来源
`text` 或 `voice`，但模型看到的对话语义一致。助手的流式文本只在 `assistant.done` 后写入
历史；被取消的半截回答不进入下一轮上下文。

Plan 2 只保留当前 WebSocket 会话内的有界历史。会话停止、连接关闭或服务重启后历史
释放，不写入磁盘。持久记忆仍属于 Plan 3。

历史以 Ollama 的 8192 token 上下文为硬上限。发送新一轮前从最旧的完整用户/助手对开始
裁剪，永远保留系统提示和当前用户消息，不拆分一轮对话。

## 协议扩展

在原 Plan 2 WebSocket 协议上增加以下客户端事件：

### `text.submit`

```json
{
  "type": "text.submit",
  "text": "请介绍一下你自己",
  "speak_response": false
}
```

- `text` 去除首尾空白后必须为 1–4000 个 Unicode 字符。
- `speak_response` 来自前端全局朗读开关。
- 事件到达时原子取消当前 LLM、TTS 和浏览器播放，随后创建新的 `turn_id`。

### `assistant.speak`

```json
{
  "type": "assistant.speak",
  "turn_id": 7
}
```

- 仅允许朗读当前会话内已经完成的助手消息。
- 后端按需合成并发送新的 `tts.chunk`，不复用或持久保存旧 WAV。
- 新用户文字或语音输入仍可立即取消这次朗读。

### `turn.cancel`

```json
{
  "type": "turn.cancel"
}
```

- 停止当前 LLM、TTS、试听和浏览器播放，但保持 WebSocket、麦克风开关与聊天记录。
- `Esc` 和界面的“停止”按钮发送该事件；`session.stop` 只用于结束整个会话并释放历史。

### `voice.select`

```json
{
  "type": "voice.select",
  "voice_key": "clear_female",
  "speed": 1.0
}
```

- `voice_key` 必须存在于服务端公开音色目录；无效值返回可恢复的 `error`。
- `speed` 只接受 `0.8`、`1.0` 或 `1.2`。
- 服务端返回 `voice.selected`，其中只包含公开 `voice_key` 和 `speed`，不泄露文件路径。

连接成功后，服务端发送 `voices.available`，包含当前可用的 `voice_key`、显示名称、风格描述、
性别分类、是否默认和是否可试听。客户端据此渲染音色卡片，不硬编码原生 `voice_id`。

### `voice.preview`

```json
{
  "type": "voice.preview",
  "voice_key": "clear_female",
  "speed": 1.0
}
```

- 服务端使用固定试听文案合成约 3–5 秒 WAV，先发送带单调递增 `preview_id` 的
  `voice.preview.chunk` 元数据，再发送对应的二进制 WAV。
- 试听不增加对话 `turn_id`，不写入聊天历史；新的试听、用户输入或停止操作会取消旧试听。
- 对话正在生成或朗读时不启动试听，返回可恢复错误；前端同时禁用试听按钮。

原有 `session.start`、二进制 PCM 帧、`audio.commit` 和 `session.stop` 保持。所有助手回复无论
是否朗读，都发送 `assistant.delta` 和 `assistant.done`。语音输入的最终文本继续使用
`asr.final`，文字输入不伪造 ASR 事件。

`session.ready` 返回当前公开模型 ID 和 `offline=true`，让顶栏明确显示“本地运行”；不得
返回模型文件路径、数据目录或会话令牌。

## 轮次状态与打断

文字和语音共用同一个单调递增的 `turn_id` 与取消令牌：

- 用户开始说话：取消旧轮次，停止浏览器播放，进入 `LISTENING`。
- 用户提交文字：取消旧轮次，保留麦克风开关状态，进入 `THINKING`。
- 用户点击停止、按 `Esc` 或发送 `turn.cancel`：取消当前生成和播放，但不结束会话。
- 用户发送 `session.stop`：取消所有任务、关闭会话并释放内存历史。
- 用户点击某条消息的“朗读”：创建只负责 TTS 的播放任务，但不增加模型对话历史。
- 所有旧轮次事件在发送前检查令牌；过期文本和音频不得进入浏览器。

语音模式默认允许说话打断。若麦克风保持开启，文字回复播放期间检测到新语音，也按同一
规则取消旧轮次。首版不提供关闭打断的设置。

## 音频和停顿行为

- 浏览器只在用户点击麦克风后申请权限。
- 浏览器上行麦克风传输固定为 signed little-endian PCM16（`pcm_s16le`）、单声道、
  16 kHz、20 ms；每帧恰为 320 samples / 640 bytes。该格式由 `session.ready` 的
  `input_audio` 公共合同声明；无头 raw bytes 不携带端序或声道头信息，服务端仅按此
  固定解释并验证帧长度。
- 服务端下行 TTS 与试听继续发送 `audio/wav`；其采样率保持引擎原生值（例如 Kokoro
  24 kHz、Melo 44.1 kHz），并由每个 `tts.chunk` 或 `voice.preview.chunk` 的
  `sample_rate` 元数据声明，不强制重采样为 16 kHz。
- 停顿档位为 `fast=0.8s`、`natural=1.35s`、`patient=2.0s`，默认 `natural`。
- 普通话未完整结尾和填充词在自然档延长至 2.0 秒。
- 不以 0.9 秒作为默认停顿阈值。
- 新输入触发后，浏览器应在 200 ms 内停止旧音频，并丢弃后续旧轮次音频。

## 错误处理

- 空文字、超过 4000 字、未知事件和非法二进制帧返回结构化 `error`，不终止可恢复会话。
- 麦克风拒绝授权时保留文字功能，并显示可恢复的中文错误。
- ASR 失败只影响当前语音轮次；用户可以立即改用文字输入。
- TTS 失败时保留完整文字回答，页面显示“朗读失败”，不撤回消息。
- WebSocket 断开时停止录音、播放和后台任务，并释放单会话锁。

## 测试与验收

自动测试必须证明：

1. 文字与语音消息按顺序进入同一历史。
2. 文字提交会取消旧语音/模型轮次，旧事件不会恢复。
3. 语音提问默认朗读；文字提问默认不朗读，开关开启后朗读。
4. 单条“朗读”只允许已完成助手消息，并可被新输入打断。
5. 麦克风拒绝授权后文字输入仍可使用。
6. 刷新或停止会话后内存历史与未播放音频被释放。
7. 键盘可使用输入框、发送、麦克风、朗读和停止控件；状态变化可被辅助技术读取。

目标机手工验收同时包含文字轮次、语音轮次、文字打断语音、语音打断文字回复，以及在
麦克风不可用时继续文字对话。还要确认左右消息名称分别为“Agent（声灵）”和“用户”，
四类音色卡片可以试听、切换和恢复默认值，刷新页面后保留公开 `voice_key` 与语速。

## 明确不做

- 不提供文字和语音两个独立会话或标签页。
- 不提供全屏电话式专属页面。
- 不持久保存聊天记录或原始音频。
- 不加入唤醒词、声纹、语音克隆、文件读取、联网搜索或系统工具。
