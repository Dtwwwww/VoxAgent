# VoxAgent 前端视觉焕新设计规范

**日期：** 2026-09-04  
**状态：** 已获用户批准  
**实施范围：** `frontend/` 目录内的界面结构、视觉样式与前端交互反馈

## 1. 目标

将现有偏工程测试页的 Web 前端升级为可直接试用的正式产品界面。视觉方向采用豆包式的明亮、柔和、圆润与亲切感，同时保留 VoxAgent 的本地 AI 属性，不复制任何第三方产品的品牌元素或具体页面。

本次改造必须保持现有文本与语音能力、通信协议、模型配置和后端行为不变。核心成果是更清晰的视觉层级、更可靠的状态反馈和更顺手的文本/语音双模式交互。

## 2. 非目标

本次不实现以下内容：

- 会话历史与侧边栏；
- 用户账号、登录或云同步；
- 文件上传、联网搜索和知识库入口；
- 新的后端接口、语音协议或模型配置；
- 未被后端支持的“重新生成”功能；
- 大面积渐变、粒子背景、持续发光或复杂品牌插画；
- 第三方 UI 组件库和新增运行时依赖。

## 3. 设计原则

1. **内容优先：** 对话是页面主体，设置与技术信息不得抢占注意力。
2. **状态可见：** 聆听、转写、思考、朗读、断线和错误必须在操作区域附近得到明确反馈。
3. **模式清楚：** 文本输入只返回文字；语音输入触发文字和自动语音回复。
4. **失败可恢复：** 错误说明具体环节，并在可恢复时提供重试入口。
5. **轻量实现：** 使用现有 React、TypeScript 与原生 CSS，不增加依赖。
6. **无障碍优先：** 保持键盘操作、可见焦点、语义化标签、44px 最小触控目标，并尊重减少动态效果设置。

## 4. 视觉系统

### 4.1 色彩

CSS 自定义属性应使用以下语义值：

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--color-page` | `#F6F7FB` | 页面暖灰背景 |
| `--color-surface` | `#FFFFFF` | 工作台、输入区、Agent 消息 |
| `--color-primary` | `#6C63E8` | 主要按钮、选中状态、强调元素 |
| `--color-primary-soft` | `#EFEEFF` | 用户消息、悬停和轻量选中背景 |
| `--color-text` | `#20212A` | 主文字 |
| `--color-text-soft` | `#737687` | 次要文字与说明 |
| `--color-success` | `#2EAF72` | 本地服务已连接 |
| `--color-warning` | `#E89B35` | 警告与重连状态 |
| `--color-danger` | `#E25555` | 录音、错误和停止操作 |
| `--color-border` | `#E8E9F0` | 分割线与控件边框 |

文字与背景必须维持可读对比度；状态不能只依靠颜色表达，还要配合图标或文字。

### 4.2 形状与阴影

- 工作台大圆角：24px；
- 消息气泡圆角：18px；
- 普通按钮圆角：12px；
- 胶囊按钮圆角：999px；
- 输入区外层圆角：22px；
- 工作台阴影：低透明度、较大模糊半径，避免明显悬浮和发光；
- 控件边框统一为 1px。

### 4.3 排版

- 使用系统字体栈，不加载网络字体；
- 正文基准字号 16px，行高 1.65；
- 页面标题 20px，字重 650–700；
- 消息发送者名称 13px，字重 600；
- 状态、时间和辅助信息 12–14px；
- 单行正文建议长度不超过约 42 个中文字符。

## 5. 页面架构

页面为居中的单列对话工作台，桌面端最大宽度 960px、高度占满可视区域。工作台从上到下分为：顶栏、消息滚动区、临近输入区的状态反馈、固定输入区。消息区独立滚动，顶栏和输入区不随消息滚出。

推荐组件边界：

- `App`：连接生命周期和顶层组合；
- `Header`：品牌、本地模型状态、当前音色与设置入口；
- `Conversation`：消息列表、欢迎空状态、自动滚动和回到底部；
- `ChatMessage`：单条消息、发送者信息和消息级操作；
- `VoiceStatus`：聆听、转写、思考、朗读和连接反馈；
- `Composer`：文本输入、麦克风、发送、停止和模式提示；
- `VoicePicker`：音色与语速选择弹层；
- `ErrorNotice`：分类错误、辅助说明和重试入口；
- `Icon`：项目内使用的内联 SVG 图标。

组件只能通过明确的 props 消费现有 `VoiceSessionController` 数据与动作，不在视觉组件中复制语音会话状态机。

## 6. 顶栏

左侧显示圆形声灵图标、标题“声灵”和副标题“你的本地语音 AI 助手”。右侧显示本地模型状态、音色入口和设置入口。

已连接时显示绿色状态点与：

> 本地运行 · `{modelId}`

连接中显示灰色或警告色状态点与“正在连接本地服务”。断开时显示红色状态点与“本地服务未连接”。顶栏不得显示 WebSocket 地址、端口、采样率或其他调试参数。

当前音色入口采用胶囊按钮，文案格式为“音色：{displayName}”。

## 7. 对话区

### 7.1 空状态

无消息时在消息区中央显示：

> 你好，我是声灵  
> 可以输入文字，或者点击麦克风和我说话。

下方提供三个建议词：“介绍一下你自己”“帮我整理今天的计划”“开始语音对话”。前两个发送文字；“开始语音对话”只聚焦或引导麦克风按钮，不擅自开始录音。文字建议词不会触发自动朗读。

### 7.2 Agent 消息

- 左对齐，最大宽度为内容区的 72%；
- 显示声灵小头像和名称“声灵”；
- 气泡使用白色背景、主文字颜色和浅边框；
- 可选显示时间，但不得用空占位数据伪造时间；
- 消息操作包含复制、朗读和停止朗读；
- 操作在触屏设备上始终可达，在精确指针设备上可于悬停或焦点时增强显示；
- 朗读状态要绑定到具体消息，让用户知道正在播放哪一条。

### 7.3 用户消息

- 右对齐，最大宽度为内容区的 68%；
- 名称固定显示“用户”；
- 背景使用 `--color-primary-soft`，文字使用深蓝紫色；
- 语音识别生成的消息可显示“语音输入”小标签；
- 不提供朗读按钮。

### 7.4 消息行为

- 生成中的 Agent 内容始终更新同一条消息，不产生碎片消息；
- 表情符号不得形成独立消息，进入 TTS 前继续沿用现有清理行为；
- 文本输入只产生文字回复；
- 语音输入产生文字回复并允许自动朗读；
- 手动朗读同一条 Agent 消息必须可以重复触发；
- 新消息到达时，如果用户处于底部附近则自动滚动；若用户主动向上浏览则不抢夺位置，并显示“回到底部”浮动按钮。

## 8. 输入区

输入区固定在工作台底部，不能遮挡最后一条消息。整体使用白色大圆角容器和轻阴影。

第一行是自适应高度文本框，占位文字为“输入消息，或点击麦克风说话”。文本框最高约 6 行，超过后内部滚动。`Enter` 发送，`Shift+Enter` 换行；输入法组合输入期间不得误发送。

第二行左侧放置麦克风按钮与模式提示，右侧放置停止生成按钮和发送按钮。发送按钮无可发送文本时禁用；有文本时使用主色实心样式。停止生成按钮只在现有控制器确实提供可用动作时展示，不添加空操作按钮。

## 9. 语音状态

状态反馈位于输入区正上方，进入状态时出现，空闲时不占空间：

| 状态 | 视觉 | 文案 | 操作 |
| --- | --- | --- | --- |
| `idle` | 不显示 | 无 | 麦克风可用 |
| `listening` | 红色呼吸点/声波 | 正在聆听，点击停止 | 麦克风变为停止按钮 |
| `transcribing` | 轻量加载图标 | 正在识别你的语音 | 暂停重复录音 |
| `thinking` | 三点动画 | 声灵正在思考 | 保留现有取消能力（若有） |
| `speaking` | 动态声波 | 正在回复 | 可停止当前朗读 |
| `connecting` | 旋转图标 | 正在连接本地服务 | 禁止依赖服务的动作 |

麦克风空闲时为白色或浅紫色按钮；聆听时变为珊瑚红，图标切换成停止方块，并使用柔和呼吸环。转写与思考期间禁止重复触发录音，但不能让整个输入区失去反馈。

## 10. 音色选择

桌面端点击顶栏音色入口打开靠右浮层，移动端使用底部抽屉。面板包含标题、当前音色、候选列表、试听按钮、语速设置和关闭按钮。

默认音色显示为 `voice-005`。候选 `engine-002`、`engine-003`、`engine-004` 按并列关系展示，不做排名或“最佳”标识。每张音色卡包含名称、简短风格描述、试听/停止按钮和选中标记。

同时只能试听一个音色。试听过程中当前按钮显示“停止”，其他试听按钮禁用，防止音频重叠。语速提供“舒缓”“自然”“稍快”三个选项，默认“自然”。面板支持 Escape 关闭、正确的焦点进入与返回，并提供清晰的可访问名称。

## 11. 错误反馈

错误不得作为对话消息插入。短暂错误显示在输入区上方；持续性服务错误显示在顶栏下方横幅。语音失败不影响已经生成的文字回复。

前端应在现有错误信息允许的范围内映射为以下用户文案：

- 后端未启动：“本地服务未启动，请启动后重试。”
- WebSocket 中断：“连接已断开，正在重新连接。”
- 麦克风权限失败：“无法使用麦克风，请在浏览器地址栏中允许麦克风权限。”
- 未检测到输入设备：“没有检测到可用的麦克风，请检查设备连接。”
- 无有效语音：“没有听清，可以靠近麦克风后再试一次。”
- 转写失败：“语音识别失败，请重新说一次。”
- 语音生成失败：“语音生成失败，你仍可阅读文字回复。”
- 自动播放失败：“浏览器阻止了自动播放，请点击朗读。”

能够安全重试的错误提供“重试”按钮；需要浏览器权限或设备操作的错误提供明确指导，不显示无效重试。

## 12. 动效

- 消息出现：透明度从 0 到 1，并从下方 6px 进入，时长 180ms；
- 浮层出现：透明度与轻微缩放组合，时长 180ms；
- 聆听呼吸环：1.4 秒循环；
- 思考状态：三个圆点依次变化；
- 朗读状态：3–4 根声波轻微变化；
- 按钮按下：缩放至 0.97，释放后恢复；
- 普通颜色、阴影和位移过渡控制在 150–220ms。

在 `prefers-reduced-motion: reduce` 下关闭循环动画和非必要位移，只保留即时状态切换。

## 13. 响应式规则

### 桌面端（宽度大于 900px）

- 工作台最大宽度 960px；
- 页面四周保留 20–32px 空间；
- Agent/用户消息最大宽度分别为 72%/68%；
- 音色选择使用右侧浮层。

### 平板端（601–900px）

- 工作台接近全宽；
- 消息最大宽度提高至 80%；
- 顶栏弱化或隐藏副标题。

### 手机端（不超过 600px）

- 页面取消明显外层卡片轮廓；
- 消息最大宽度为 88–90%；
- 音色面板改为底部抽屉；
- 麦克风、发送、关闭等触控目标不得小于 44×44px；
- 输入区必须考虑安全区和软键盘，不得遮挡文本框与主操作；
- 顶栏仅保留名称、连接状态、音色/设置入口的必要部分。

## 14. 无障碍要求

- 所有图标按钮必须有 `aria-label`；
- 当前选中状态使用 `aria-pressed` 或语义等效属性；
- 音色面板需具备对话框语义、标题关联和焦点管理；
- 状态更新使用克制的 `aria-live`，避免流式内容频繁打断读屏；
- 错误信息需与相关控件建立语义关联；
- 键盘焦点环清晰可见，不能仅依赖浏览器默认弱轮廓；
- 不得用颜色作为状态的唯一表达方式。

## 15. 测试策略

前端现有测试必须保持通过，并增加以下高价值行为测试：

1. 空状态和建议词的展示与操作；
2. Agent 在左、用户在右，且用户名称为“用户”；
3. 文本提交不会触发自动朗读；
4. 语音状态对应正确文案和按钮状态；
5. 同一条 Agent 消息可以重复朗读；
6. 错误不会插入消息列表，且可恢复错误显示重试入口；
7. 音色面板打开、选择、试听互斥和关闭行为；
8. 消息自动滚动与“回到底部”行为；
9. 关键按钮具备可访问名称和禁用状态；
10. TypeScript 类型检查与生产构建通过。

视觉验收至少覆盖 1440px 桌面宽度和 390px 手机宽度，检查消息对齐、输入区遮挡、弹层位置、长文本换行、状态切换和键盘焦点。

## 16. 完成标准

- 页面第一眼呈现为正式、亲切、可信赖的本地 AI 产品；
- Agent 与用户消息能快速辨认，用户名称显示为“用户”；
- 底部输入、思考状态与麦克风状态不重叠、不抢占对话空间；
- 文本输入只返回文字，语音输入才自动播放回复；
- 同一条 Agent 消息可重复朗读，表情不生成独立消息且不进入 TTS；
- 服务、权限、录音、识别、生成和播放错误有明确区分；
- 桌面与手机端均可正常完成文本和语音对话；
- 不修改现有后端协议、模型配置和语音状态机职责；
- 前端测试、类型检查和生产构建全部通过。
