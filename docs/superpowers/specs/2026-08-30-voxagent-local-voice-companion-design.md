# 声灵：本地语音伙伴项目设计

**日期：** 2026-08-30  
**状态：** 已确认设计，等待用户审阅文档  
**目标平台：** Windows 11 单机、单用户  
**产品定位：** 将本地桌面语音助手与有性格、有长期记忆的 AI 陪伴角色结合起来。

## 1. 项目目标

声灵第一版是一个本地优先的 Windows 桌面应用。用户点击开始后，可以与固定人格的 AI 连续语音对话；AI 能记住经授权保存的偏好和事件，也能在受控权限下搜索本地知识、查找文件、打开应用以及管理待办和提醒。

系统默认在本机完成录音处理、语音识别、语言模型推理、记忆检索和语音合成。云端能力默认关闭，只有在用户看到待发送内容、服务商和用途并单次确认后才能调用。

### 1.1 第一版成功标准

- 点击后进入连续语音会话，退出会话后不监听麦克风。
- 能自动判断用户说完、生成回答、流式朗读，并允许用户随时打断。
- 同一个人格同时承担陪伴和助手职责，不要求用户手动切换模式。
- 能保存、查询、编辑和删除长期记忆。
- 能安全执行第一版白名单工具，且不能直接运行任意 PowerShell 或 Shell 命令。
- 断网时语音对话、记忆、本地知识库和本地工具仍可用。
- 能在目标电脑的 GTX 1660 Ti 6GB 显存与 16GB 内存条件下稳定运行。

### 1.2 第一版不做

- 唤醒词常驻监听。
- 任意命令执行、文件删除/移动、软件安装和自动填写网页表单。
- 声音克隆、多角色并行、多人账户。
- Live2D、摄像头视觉、屏幕理解和桌面宠物模式。
- 手机端、局域网远程访问和公网部署。
- 模型训练或微调。

这些能力保留为后续独立迭代，避免影响第一版语音闭环、记忆可靠性和权限安全。

## 3. 总体架构

采用“Web 技术前端 + Windows 桌面壳 + Python 本地后端”的三部分结构。

### 3.1 桌面前端

- React + Vite 实现聊天、字幕、状态、人设、记忆、知识库、工具确认和设置界面。
- Electron 将同一套 Web 前端封装成 Windows 安装程序和桌面应用。
- 开发阶段可以在浏览器中调试；发布后用户运行 `.exe`，不需要手动打开浏览器。
- 麦克风通过 Web Audio API 采集，音频帧经本机 WebSocket 发送给后端。
- Electron 只提供窗口、托盘、通知、快捷键和安全 IPC，不直接拥有模型或工具执行逻辑。
- Electron 负责启动固定的 Python 后端入口、检查健康状态并在应用退出时关闭后端；LLM 无法修改启动命令或创建其他子进程。

### 3.2 本地后端

- Python + FastAPI 提供本机 HTTP/WebSocket API。
- 服务只绑定 `127.0.0.1`，使用每次启动生成的会话令牌；令牌经受限 Electron preload API 传给前端，不写入 Local Storage；禁止通配 CORS。
- 后端包含会话状态机、端点检测、ASR、LLM 适配器、流式分句、TTS、记忆、知识检索、工具策略和云端授权网关。
- 所有模型和外部服务均通过稳定接口适配，使 ASR、LLM、TTS 可以独立替换。

### 3.3 本地模型服务

- 第一版使用 Ollama 提供本地 LLM API，降低安装和模型管理成本。
- 后续需要更精细的 GPU 层数、KV Cache 和显存控制时，可切换到 `llama.cpp server`；上层只依赖兼容的聊天 API，不绑定具体推理器。
- LLM 使用 GPU；VAD、ASR、TTS 和嵌入模型默认使用 CPU，避免多个模型争抢 6GB 显存。

## 4. 一次语音对话的数据流

1. 用户点击“开始对话”，前端申请麦克风权限并创建会话标识。
2. 前端持续发送 16kHz 单声道音频帧；VAD 判断有声区间和候选停顿。
3. 端点控制器在候选停顿时执行低频临时识别，结合停顿长度和句尾是否明显未完成决定是否继续等待。
4. 最终语音片段送入 ASR；原始音频只保留在内存中，识别完成或失败重试结束后立即释放。
5. 对话编排器加载人格、当前会话摘要、相关长期记忆和相关知识片段。
6. LLM 流式生成文本。若输出工具请求，权限模块校验工具名、参数、路径和权限等级；需要确认的操作先发回前端预览。
7. 普通回答或工具最终结果经流式分句器切分。第一段完整短句立即送入 TTS，后续句子按顺序进入合成队列。
8. 前端播放音频并显示字幕。用户再次开口时，系统立即取消当前 LLM 请求、TTS 任务和播放队列，再进入监听状态。
9. 对话结束后，记忆模块只提取长期有用且不敏感的信息；用户可以在会话摘要中查看和撤销。

所有异步任务携带 `session_id` 和递增的 `turn_id`。任何取消、断线或新一轮输入都会使旧 `turn_id` 失效，防止上一轮音频或工具结果串入当前对话。

## 5. 模型与语音组件

### 5.1 LLM

第一版设置三个本地档位：

| 档位 | 模型 | 用途 |
|---|---|---|
| 默认 | Qwen3-4B-Instruct-2507，Q4_K_M | 约 2.5GB 权重，非思考模式，给 6GB 显存留下较多语音与桌面余量 |
| 质量 | Qwen3.5-4B，Q4_K_M | Ollama 版本约 3.4GB，中文、工具调用和综合能力更强，但显存余量更小 |
| 低资源 | Qwen3-1.7B，Q4_K_M | 内存或显存不足时自动建议切换，保证基础对话可用 |

默认关闭深度思考，实际上下文限制在 4K–8K。长期历史通过摘要和记忆检索注入，不依赖超长上下文。Qwen3.5-4B 的模型卡和 Ollama 包信息分别见 [Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B) 与 [Ollama qwen3.5:4b](https://ollama.com/library/qwen3.5:4b)；Qwen3 系列的本地运行说明见 [Qwen3](https://github.com/QwenLM/Qwen3)。

第一阶段必须在目标电脑上对默认和质量档进行同一组中文闲聊、记忆提取和工具调用基准测试。只有质量档同时满足显存不超过 5.4GB、首个文本片段不慢于 3 秒且 30 分钟稳定运行，才允许成为用户可选的常用档位。

### 5.2 VAD 与停顿策略

- 使用 Silero VAD ONNX，在 CPU 单线程上运行。
- 默认“自然”停顿判定为 1.2–1.5 秒。
- “快速”模式约 0.8 秒；“耐心”模式约 2 秒。
- 候选停顿先触发预处理，不立即提交给 LLM。若临时识别结果以“嗯、然后、但是、我觉得、我想想”等未完成表达或明显连接词结尾，等待时间延长到约 2 秒。
- 用户可在设置中选择三档，并能试听实际效果。

Silero VAD 项目见 [snakers4/silero-vad](https://github.com/snakers4/silero-vad)。

### 5.3 ASR

- 默认使用 SenseVoiceSmall INT8，通过 sherpa-onnx 在 CPU 上运行。
- 第一版主要处理普通话和中英混合语音；保留情绪与声音事件标签作为陪伴回复的弱提示，不能据此作医疗或心理判断。
- 为字幕和候选停顿提供低频临时识别；最终文本只在端点确认后提交。
- 若目标电脑上的临时识别延迟不满足要求，临时字幕适配器切换为 sherpa-onnx 的中英流式 Paraformer INT8，SenseVoice只负责最终识别和可选情绪标签。

组件资料见 [SenseVoice](https://github.com/FunAudioLLM/SenseVoice)、[sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) 和 [流式中英 Paraformer](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/online-paraformer/paraformer-models.html)。

### 5.4 TTS

- 默认使用 sherpa-onnx 的 Kokoro 多语言 INT8 模型，在 CPU 上合成中文和中英混合文本。
- MeloTTS 作为备用中文音色引擎。第一阶段用固定中文脚本进行真人盲听和首段延迟测试；默认仍保持 Kokoro，只有 MeloTTS 同时获得更高自然度评分且首段延迟不超过 1.2 秒时才在设置中将其标记为“推荐中文音色”。
- 流式分句优先在 `。！？；` 和可安全停顿的逗号处分割；第一段目标为 12–30 个汉字，避免极短片段造成机械停顿。
- CosyVoice 3、GPT-SoVITS 和声音克隆不进入第一版。它们可以作为后续“高质量语音模式”独立评估，不能与 4B LLM 默认同时占用 GPU。

资料见 [Kokoro](https://github.com/hexgrad/kokoro)、[sherpa-onnx Kokoro 中文模型](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html)、[MeloTTS](https://github.com/myshell-ai/MeloTTS) 和 [CosyVoice](https://github.com/QwenAudio/CosyVoice)。

## 6. 人格与对话行为

声灵只有一个当前人格，不设置彼此割裂的“陪伴模式”和“助手模式”。对话编排器根据用户意图决定直接聊天、检索记忆、查询知识或提出工具请求。

人格配置包含：名称、对用户称呼、背景、性格、关系定位、表达风格、主动程度、禁区和默认回复长度。语音回复默认口语化和简短；复杂问题先朗读结论，详细内容继续显示在窗口中。

工具执行状态必须来自真实工具结果。模型在确认前只能说“准备打开”或“需要确认”，不能说“已经完成”。

## 7. 长期记忆与知识库

### 7.1 四层记忆

- **会话记忆：** 当前会话最近若干轮和滚动摘要，受 4K–8K 上下文约束。
- **用户档案：** 称呼、稳定偏好、重要人物、习惯和用户明确要求记住的信息。
- **事件记忆：** 值得长期保留的经历、决定和会话摘要。
- **任务记忆：** 待办、提醒、状态和完成时间。

用户明确说“记住”时直接创建可见记忆；自动提取只保存长期有用、置信度足够且不敏感的候选项。用户能在记忆页面查看来源、编辑、删除，也可以在对话中说“忘掉这件事”。

密码、访问令牌、身份证号、银行卡号和完整原始录音禁止自动保存。删除记忆时同时删除对应向量；数据库备份遵循相同删除策略。

### 7.2 数据存储

SQLite 数据库至少包含以下逻辑实体：

- `conversations`：会话元数据和摘要。
- `messages`：用户与 AI 的文字消息，不包含原始音频。
- `profile_facts`：稳定用户事实及来源、置信度、更新时间。
- `episodes`：事件记忆及时间范围。
- `reminders`：待办、提醒时间和状态。
- `knowledge_documents`：用户授权文件的路径、哈希和索引状态。
- `knowledge_chunks`：文本片段、来源位置和嵌入向量。
- `tool_audit`：工具请求、确认、参数摘要和真实结果。

数据库开启 WAL 和事务。每日首次退出时生成一个滚动本地备份，保留最近 7 份；备份只位于 `D:\VoxAgentData\data\backups`。

### 7.3 语义检索

使用 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5) 在 CPU 上生成 512 维向量。模型仅 24M 参数，权重约 96MB。第一版将向量以 BLOB 保存在 SQLite，并用 NumPy 对个人规模数据做余弦相似度检索，不引入独立向量数据库。

知识库只索引用户主动添加的文件或目录，第一版支持 TXT、Markdown、PDF 和 DOCX。文档中的指令被视为不可信数据，不能覆盖系统提示、权限策略或工具确认规则。

## 8. 安全工具

| 等级 | 第一版能力 | 规则 |
|---|---|---|
| L0 只读 | 搜索已授权目录、查询本地知识库 | 可以直接执行，记录审计信息 |
| L1 可见动作 | 打开白名单应用、打开明确文件 | 前端显示目标并要求一次确认 |
| L2 数据变更 | 新增、修改、完成待办或提醒 | 前端显示变更前后内容并要求确认 |
| L3 高风险 | 删除/移动文件、任意命令、安装软件、网页自动提交 | 第一版禁止 |

LLM 只能输出符合 JSON Schema 的结构化请求。权限模块负责：

- 将相对路径解析为规范绝对路径。
- 拒绝路径穿越、符号链接越界和未授权目录。
- 对应用使用明确白名单，不接受模型生成的可执行文件路径。
- 将确认绑定到请求哈希和当前 `turn_id`，参数变化后必须重新确认。
- 不把 PowerShell、`cmd.exe` 或任意子进程接口暴露给 LLM。

## 9. 云端增强与隐私

云端网关默认关闭。每次调用前必须展示：调用原因、服务商、将发送的文字或文件、预计用途，以及“仅本次允许”按钮。未被当前任务选中的长期记忆、聊天历史和本地文件不能附带发送。

API 密钥存入 Windows Credential Manager，不写入仓库、SQLite、日志或前端配置。日志默认不记录完整提示词和文件内容；诊断模式必须由用户主动开启并明确显示状态。

桌面前端启用严格 Content Security Policy，不加载远程脚本，不在渲染进程开放 Node.js；所有系统能力只能经类型明确的 preload IPC 和后端权限模块调用。

## 10. 性能和资源目标

下列指标是目标电脑上的验收门槛，不是基于其他显卡的宣传数据：

| 指标 | 目标 |
|---|---|
| 点击后进入监听 | 1 秒以内 |
| 默认自然停顿 | 1.2–1.5 秒，可延长到约 2 秒 |
| 最终 ASR 文本 | 端点确认后约 1 秒内 |
| LLM 首个文字片段 | 端点确认后 1.5–3 秒 |
| 第一段声音播放 | 用户说完后总体 3–5 秒 |
| 用户打断到停止播放 | 300 毫秒内 |
| GPU 显存 | 峰值不超过约 5.4GB |
| 稳定性 | 30 分钟连续对话无崩溃、无旧轮次串音 |

启动器检查 C/D 盘空间、可用内存、GPU 和模型状态。若资源不足，按顺序降低上下文、关闭非必要临时字幕、建议切换低资源 LLM；不能未经用户同意自动转到云端。

## 11. 异常处理

- **麦克风不可用：** 显示设备选择和权限说明，文字输入保持可用。
- **无有效语音：** 不调用 LLM，保持监听并显示轻量提示。
- **ASR 失败：** 在内存中最多重试一次，随后释放音频并允许用户重说。
- **LLM 加载或显存失败：** 缩短上下文或建议低资源档；不循环重启模型。
- **TTS 失败：** 保留文字回答，切换备用引擎或允许重试，不阻塞下一轮输入。
- **工具拒绝或失败：** 显示真实状态和可操作建议，不伪造成功，不自动升级权限。
- **网络不可用：** 本地核心不受影响；云端入口显示不可用。
- **应用异常退出：** SQLite 事务和 WAL 保证已提交数据，重启后清理未完成的临时任务。

## 12. 测试与验收

### 12.1 自动测试

- 端点控制器：快速、自然、耐心三档以及未完成表达延时。
- 会话状态机：监听、识别、生成、合成、播放、打断和旧 `turn_id` 作废。
- 流式分句器：中文标点、数字、中英混合、超长无标点文本。
- 记忆规则：显式记忆、自动候选、敏感信息拒绝、编辑与级联删除。
- 工具策略：合法调用、未知工具、无效 Schema、路径穿越、授权目录越界和确认哈希变化。
- 知识库：四种文件格式、增量重建、删除文件和文档提示注入。

### 12.2 集成测试

- 固定 WAV 样本经过 VAD、ASR、对话编排和 TTS 的完整链路。
- 使用模拟 LLM 流验证首句分段、取消和播放队列清理。
- 使用临时目录和模拟应用验证 L0/L1/L2 工具，不操作真实用户文件。
- 断网环境验证本地会话、记忆、知识检索和工具可用。

### 12.3 目标电脑人工验收

- 20 次普通话及中英混合对话。
- 20 次在 AI 说话期间的随机打断。
- 10 次工具确认，覆盖允许、取消、参数变化和失败。
- 一次 30 分钟连续会话。
- 对 Qwen 两个 4B 候选记录首 token、生成速度、RAM、VRAM 和温度。
- 对 Kokoro 与 MeloTTS 使用同一组中文脚本进行盲听和首段延迟比较。

## 14. 分阶段交付

本设计包含模型基准、语音闭环、记忆知识、工具安全和桌面打包等多个可独立验收的子系统。详细实施阶段应为下列六个阶段分别编写有先后依赖的实施计划；每个计划都必须产生可运行、可测试的增量，不能合并成一个无法逐段审查的巨型计划。

1. **硬件与模型基准（1–2 天）：** 安装运行时；验证 Qwen 两个 4B 候选、低资源模型、SenseVoice、Kokoro 和 MeloTTS；形成目标电脑基准记录。
2. **纯语音闭环（4–6 天）：** 完成点击会话、VAD/端点、ASR、LLM 流、TTS 队列、字幕和打断。
3. **人格与长期记忆（4–6 天）：** 完成人格配置、四层记忆、查看/编辑/删除和知识库。
4. **安全助手工具（4–6 天）：** 完成 L0/L1/L2 工具、确认界面、路径策略和审计记录。
5. **桌面产品化（4–6 天）：** 完成 Electron 打包、安装向导、数据目录、资源检查、日志和恢复。
6. **验收与优化（3–5 天）：** 在目标电脑执行完整测试，修正延迟、内存、声音和打断问题。

对熟悉 Python、React 和本地模型部署的单人开发者，第一版预计为 4–6 周。时间估算不包含 Live2D、声音克隆、深度电脑控制和云端账户系统。

## 15. 关键设计决定

- 选择轻量自建核心，按需复用开源组件，不深度绑定单个伴侣或语音框架。
- 前端采用 React Web 技术，最终通过 Electron 作为 Windows 桌面应用交付。
- 4B 量化 LLM 独占主要 GPU 资源，语音和检索默认走 CPU。
- 通过摘要和本地检索实现长期记忆，不使用超长上下文维持全部历史。
- 默认停顿 1.2–1.5 秒并自适应延长，避免 0.9 秒固定端点截断自然表达。
- 所有有副作用的工具调用必须经过独立策略层和用户确认；第一版无任意命令能力。
- 本地优先不是“离线能力不足时自动上传”，而是云端每次都要明确、可见、单次授权。
