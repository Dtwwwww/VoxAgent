# VoxAgent 混合实时语音设计

日期：2026-09-05

状态：用户已确认

范围：Plan 2 语音链路改造，不改变 Plan 3 的记忆、知识库和人格能力

## 1. 目标

把当前“点击录音、手动停止、整段识别、整段生成语音”的交互改造成接近电话通话的连续语音体验：用户只需开始一次通话，系统持续监听、显示临时字幕、自动判断说话结束、流式回答并按短句快速发声；用户再次开口时立即停止 Agent 朗读。

系统采用双模式：默认使用免费、免 API Key 的浏览器语音能力；浏览器不支持、网络不可用或在线语音失败时，自动回退到本地 SenseVoice/Paraformer/Kokoro。文字输入保持只返回文字，不自动发声。

## 2. 已确认的约束

- 运行环境：Windows，本机 Intel i5-9300H、16 GB 内存、GTX 1660 Ti 6 GB。
- LLM 继续通过本机 Ollama 运行，不迁移到云端。
- 在线语音优先免费，不引入必须付费的语音 API。
- 目标麦克风是笔记本内置 Realtek 麦克风阵列。
- 保留离线能力，并允许用户手动切换“在线优先”和“仅本地”。
- 保留现有文本对话、RAG、记忆、人格、复制和单条消息朗读能力。

## 3. 根因证据

### 3.1 麦克风

Windows 设备层能看到 Realtek 麦克风输入，同时存在 ToDesk 和 XReal 虚拟音频设备。当前前端调用 `getUserMedia()` 时没有枚举和选择 `deviceId`，只能依赖系统或浏览器默认输入，因此可能录到虚拟设备或静音源。当前采集约束还关闭了回声消除和降噪，也没有音量反馈，用户无法判断应用是否真正收到声音。

### 3.2 识别与实时交互

本地链路已经有 Paraformer 部分识别器，但协议没有把部分结果发送给前端。LLM 仅在手动提交或端点提交后的最终 SenseVoice 识别完成后启动，因此当前架构不是连续实时对话。

### 3.3 语音质量与延迟

在目标机器上使用同一句中文进行“合成后再由 SenseVoice 回识别”的诊断：

| 引擎 | 合成耗时 | 音频时长 | 回识别结果 | 结论 |
| --- | ---: | ---: | --- | --- |
| Melo voice 0 | 1.684 秒 | 1.249 秒 | `The is.` | 快，但当前模型/前端配置生成的中文不可用 |
| Kokoro voice 3 | 10.909 秒 | 3.806 秒 | 完整中文，仅“声灵”同音误识别为“生灵” | 可懂，但 CPU 合成太慢 |

因此不能继续把 Melo 当作默认音色，也不能只靠 Kokoro 达成低延迟目标。

## 4. 方案选择

### 4.1 主方案：浏览器实时语音优先

在线优先模式使用 Web Speech API：

- `SpeechRecognition`/`webkitSpeechRecognition` 提供中文连续识别和中间结果。
- `speechSynthesis` 提供当前系统或浏览器可用的中文音色。
- 功能检测失败时不报废会话，而是立即回退本地链路。

该方案免费、无需密钥、首版改造量可控，最适合当前硬件。浏览器实现可能调用平台在线服务，所以界面必须明确显示当前是“浏览器在线语音”还是“本地离线语音”。

### 4.2 可选实验能力：Edge 在线音色

未来可把 `edge-tts` 作为实验性语音提供器，不能作为唯一或默认依赖。它无需 API Key、音色通常更自然，但依赖非正式在线接口，稳定性和长期可用性没有保证。实验提供器失败时必须回退浏览器系统音色或本地 Kokoro。

### 4.3 暂缓：全本地 CosyVoice

CosyVoice 3 支持双向流式 TTS，但在 6 GB 显存上需要与 Ollama 争抢资源。首版不部署；后续必须先做独立显存、首包延迟和稳定性基准，再决定是否加入。

## 5. 总体架构

语音能力通过前端统一的 `RealtimeVoiceController` 管理，业务界面不直接调用浏览器或本地语音实现。

```text
设备选择与音量检测
        │
        ▼
RealtimeVoiceController
   ├─ BrowserSpeechProvider ── 浏览器连续 ASR + 浏览器 TTS
   └─ LocalSpeechProvider   ── PCM WebSocket + Paraformer/SenseVoice + Kokoro
        │
        ▼
统一会话状态机 ── Ollama 流式回答 ── 分句器 ── TTS 播放队列
```

### 5.1 `MicrophoneDeviceManager`

职责：

- 首次授权后调用 `enumerateDevices()` 获取所有 `audioinput`。
- 展示设备名称，区分名称中含 Virtual、ToDesk、XReal 的虚拟设备。
- 默认优先上次保存的设备；首次使用时优先名称含 Realtek、Microphone Array 或“麦克风阵列”的设备。
- 仅在找不到实体设备时使用浏览器默认输入。
- 将选中的 `deviceId` 写入 `getUserMedia` 的精确约束。
- 保存的仅是设备 ID 和显示名称，不保存音频。

采集约束：单声道、自动增益、回声消除和降噪均开启。若浏览器不支持某个约束，应降级继续采集，并在诊断信息中记录实际 `MediaTrackSettings`。

### 5.2 `InputLevelMeter`

从同一个媒体流计算短窗 RMS/峰值，只向 UI 发布归一化音量等级，不保存原始音频。开始采集后 100 毫秒内显示变化；连续 3 秒低于静音阈值时提示“没有检测到声音，请检查麦克风”。

### 5.3 `BrowserSpeechProvider`

- 语言固定优先 `zh-CN`。
- 优先调用标准定义的 `recognition.start(selectedAudioTrack)`，把设备管理器选中的 Realtek 音轨交给识别器。
- 启动前做真实能力探测，不能只检查构造函数是否存在。若当前浏览器不支持音轨参数，则仅当浏览器默认输入与所选 Realtek 设备一致时使用无参数 `start()`；否则回退本地识别并明确提示。
- 开启 `continuous` 和 `interimResults`。
- 临时结果更新右侧半透明用户气泡；最终结果合并为一次正式提交。
- 浏览器识别自然结束但通话仍开启时，受控重启识别器。
- `speechSynthesis` 只选择 `zh-CN`、`zh-HK`、`zh-TW` 或明确中文的可用音色。
- Agent 文本按标点与最大长度分句，完整短句一出现即可排队朗读，不等待整段回答。
- `speechSynthesis.cancel()` 必须在用户打断、切换模式、结束通话和会话重置时执行。

### 5.4 `LocalSpeechProvider`

- 保留现有 16 kHz、PCM16、20 ms WebSocket 音频协议。
- 新增部分转写服务器事件，把 Paraformer 的更新发送给前端。
- 最终提交仍以 SenseVoice 结果为准。
- 本地 TTS 默认使用可懂的 Kokoro；Melo 从用户可见列表移除。
- 本地模式明确提示“离线朗读生成较慢”，不伪装成低延迟模式。

### 5.5 `RealtimeVoiceController`

统一状态：

```text
off → connecting → listening → user_speaking → transcribing
    → thinking → responding → speaking → listening
```

允许的中断：

- 任意活动状态可进入 `off`。
- `speaking` 检测到用户开口后进入 `user_speaking`，同时取消所有待播语音和当前 LLM/TTS 输出。
- 在线提供器产生能力错误、网络错误或重复无结果时进入 `fallback`，然后切换本地提供器并回到 `listening`。
- 单条文字消息提交不进入连续通话状态机，也不会触发自动 TTS。

打断信号优先使用识别器的 `speechstart` 或本地 Silero VAD，不使用单纯的音量阈值直接判定说话，避免扬声器回声误触发。`InputLevelMeter` 只承担设备诊断和视觉反馈。Agent 朗读期间麦克风流保持打开，回声消除必须开启。

## 6. 对话数据流

### 6.1 在线优先

1. 用户点击“开始实时通话”。
2. 选择并打开 Realtek 麦克风，音量条开始更新。
3. 浏览器识别器持续产生临时字幕。
4. 浏览器产生最终识别结果后，前端向后端提交文本，并标记来源为语音。
5. 后端通过本地 Ollama 流式生成回答。
6. 前端分句器发现完整短句后立即调用浏览器 TTS。
7. 用户再次开口时，前端立即取消浏览器 TTS、清空未播句子并通知后端取消旧轮次。
8. 新一轮最终识别结果继续进入同一会话历史。

### 6.2 本地回退

1. 前端保留同一麦克风流，把 PCM 帧发送至本地 WebSocket。
2. Paraformer 部分结果通过新事件显示为临时字幕。
3. VAD 与端点检测自动提交后，SenseVoice 生成最终文本。
4. Ollama 流式回答；本地 Kokoro 按短句生成并播放。
5. 用户开口时保留现有 barge-in 取消语义。

模式切换不能创建新的对话历史，也不能清空 RAG、记忆或人格上下文。

## 7. 用户界面

### 7.1 通话控制

- 主按钮：“开始实时通话”/“结束通话”。
- 模式：“在线优先”/“仅本地”，默认在线优先。
- 麦克风选择器显示当前设备名称；虚拟设备带“虚拟”标签。
- 音量条紧邻麦克风名称，静音时给出可执行提示。
- 在线能力失败后显示非阻塞提示“已切换到本地语音”。

### 7.2 状态栏

底部状态栏只显示当前最重要状态：正在连接、正在监听、检测到你在说话、正在识别、Agent 正在思考、Agent 正在回复、Agent 正在朗读、你已打断 Agent、已切换到本地模式。

### 7.3 消息

- 临时用户字幕使用右侧半透明气泡；最终结果在原位置固化为“用户”消息，避免重复消息。
- Agent 文字持续流式显示。
- 被打断的 Agent 文字保留，语音队列停止。
- 每条 Agent 消息保留复制、朗读和停止朗读。
- 手动朗读使用当前模式与当前音色；失败时按同一回退策略处理。

## 8. 错误与回退

| 条件 | 用户可见行为 | 系统行为 |
| --- | --- | --- |
| 麦克风权限拒绝 | 提示允许权限，文字仍可用 | 不反复弹权限请求 |
| 选中虚拟或无声设备 | 提示切换 Realtek | 保持设备选择器可操作 |
| 浏览器不支持识别 | 显示已切换本地 | 启动本地 PCM 链路 |
| 在线识别网络错误 | 显示已切换本地 | 取消在线识别并复用麦克风流 |
| 浏览器没有中文音色 | 显示本地朗读较慢 | 使用 Kokoro |
| 在线 TTS 播放失败 | 一次自动回退 | 不重复朗读同一短句 |
| 本地 ASR 无结果 | 提示没有检测到有效语音 | 回到监听，不创建空消息 |
| 本地 TTS 失败 | 保留文字回答 | 回到监听，不断开 WebSocket |

在线与本地都失败时，语音通话暂停但文字会话继续可用。

## 9. 隐私与安全

- 在线优先模式可能由浏览器平台服务处理语音，首次开启时必须明确提示。
- 仅本地模式不调用浏览器在线识别或非本机语音服务。
- 不记录原始麦克风音频，不上传到项目后端之外的自建服务。
- 设备 ID 只保存在浏览器本地设置中。
- 现有会话 token、回环地址限制和服务端音色内部 ID 隔离保持不变。

## 10. 性能目标

- 麦克风音量反馈：采集开始后 100 ms 内。
- 在线临时字幕：开始说话后 0.5–1.5 秒内出现。
- 正常停顿自动提交：约 1–1.5 秒；未完成句尾最多约 2 秒。
- 打断 Agent：检测到用户开口后 300 ms 内停止声音。
- Agent 首个文字：最终提交后目标 1 秒内。
- 在线首次发声：首个完整短句出现后 0.3–1 秒。
- 本地回退不承诺同等 TTS 延迟，但必须保证中文可懂。

性能目标按 p95 记录；浏览器或平台语音服务不可用不算达到目标，但必须正确回退。

## 11. 验收标准

1. 设备列表能看到并选择 Realtek 麦克风，刷新后仍保持选择。
2. 对着 Realtek 麦克风说话时，音量条明显变化；选择静音虚拟设备时出现诊断提示。
3. 在线优先模式连续说三句中文，临时字幕和最终文本能正确更新且不重复。
4. 用户不点击停止，正常停顿后会自动提交。
5. Agent 回答按短句开始发声，中文清楚、顺序正确且无表情朗读。
6. Agent 朗读期间用户再次开口，声音在 300 ms 内停止，旧语音不会恢复。
7. 禁用网络或模拟在线能力错误后，界面提示并自动切换本地模式，仍能完成一轮语音对话。
8. 文字输入只返回文字，不自动发声。
9. 在线语音失败不关闭 WebSocket、不丢失会话历史、RAG 来源或记忆上下文。
10. 不再向用户提供当前不可懂的 Melo 音色。

物理麦克风、浏览器在线识别和实际扬声器打断必须在目标电脑上人工验收；自动测试不能替代这些检查。

## 12. 首版范围外

- 多人同时说话与说话人分离。
- Agent 与用户同时持续发声的真全双工混音。
- 声纹身份、声音克隆和情绪驱动音色。
- CosyVoice 本地部署与 GPU 并发调度。
- 所有移动端浏览器兼容。
- 付费语音 API。
